## Codex review round (PR #119)

Codex reviewed d0127a8 (manual `@codex review`); two findings, both verified real and fixed on this branch. Re-verification re-ran every gate at 7c98c1b (numbers above), zero paid calls.

- P1 "Regenerate the extension bundle with the adapter fix" — CONFIRMED, FIXED (4931382). `src/extension/content.js` is a committed bundle built by `scripts/build-phase0.js` from `src/runtime/content-script.js` (the adapter is in its graph); it still carried the old sendMove, so the shipped extension dropped every move on keyboard-deaf pages. `build-fresh.test.mjs` failed at d0127a8 (observed: "content.js is stale"); the packet's earlier verification ran the gauntlet suite plus three src files (adapter/autodetect/hud-a11y) and missed this surface. Rebuilt with the repo's own tooling; build-fresh green (2/2) and byte-deterministic.
- P2 "Resolve jsdom through the repository test dependency setup" — CONFIRMED, FIXED (e21e8b9). The new adapter test statically imported jsdom and relied on an ancestor `node_modules`; in a normal checkout the documented command failed with ERR_MODULE_NOT_FOUND before any assertion. It now uses the same self-setup as `phone.test.mjs` / `hud-a11y.test.mjs` (node_modules symlink into NODE_TEST_ROOT, default `../hud-test-deps`) and imports jsdom dynamically, so it passes standalone.
- Found while re-running the full root src surface at the rebuilt head: `phone.test.mjs`'s claimed-keyboard stub returned `undefined`, which under the f09 contract is an UNCLAIMED keydown — sendMove correctly fell back to touch and the one-move-per-sendMove assertion failed `1 !== 0`. The real page's `keyboard_input_manager.js` preventDefaults every mapped key, so the stub now models a claimed keydown (returns true) (7c98c1b). Fail-before observed at the pre-fix head; phone.test 6/6 after.
